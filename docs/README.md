# OctoAcme — Project Management Processes (Overview)

OctoAcme runs projects iteratively through a clear lifecycle: initiation, planning, execution, release, and close/retrospective. Initiation captures a concise one‑pager to confirm the business need and success metrics; planning turns approved initiatives into a prioritized backlog with acceptance criteria, estimates, and a Definition of Done; execution uses small, focused increments tracked on a project board; release follows pre‑release checks, smoke tests, and automated pipelines; and retrospectives convert learnings into prioritized action items that feed back into the backlog.

Work is tracked on a project board with columns Backlog → Ready → In Progress → In Review → QA → Done. Pull requests should be small when practical, include the related issue and acceptance criteria in the description, and pass CI and security scans before merging. The repository includes templates and checklists (one‑pager, backlog item, release notes, risk register) to keep planning and execution consistent.

Roles and ownership are explicit: Product Managers define outcomes and success metrics, Project Managers coordinate delivery and communications, Developers implement and maintain tests and documentation, and QA validates acceptance criteria with both automated and manual checks when needed. Persona definitions and responsibilities are documented so teams can align quickly and share accountability.

Communication follows a simple cadence: daily standups for progress and blockers, weekly delivery syncs and PM–PdM alignment, monthly stakeholder updates, and ad‑hoc escalations following defined escalation paths. Quality assurance combines unit and integration tests, CI security scanning, and end‑to‑end smoke tests for critical flows; manual QA is used for feature acceptance and post‑release verifications. Continuous improvement is enforced via retrospectives, tracked action items, and a living risk register with weekly reviews and escalation paths.
